# Security policy

## Reporting a vulnerability

Please report security issues privately rather than opening a public issue.

Use GitHub's private vulnerability reporting on this repository:
**Security → Report a vulnerability**. That opens a private advisory visible
only to the maintainers. If that button is not there (the form is off until the
repository's owner switches it on), open an issue that says you have a security
report and asks for a private channel, and leave the details out of it.

Include what you need to make the problem reproducible: the affected version
or commit, the steps or input that trigger it, and what you observed. A proof
of concept helps but is not required.

This is a small project maintained in spare time, so there is no response-time
guarantee. Reports are read and acted on in order of severity.

## Scope

In scope: the code in this repository, including anything it does with input
that comes from outside it (files, share links, imported data, network
responses, user-supplied text rendered into a page), and the website it
publishes: a way past the Content-Security-Policy or its Trusted Types, a way
to frame the app on a host that sends headers or to make it run in another
site's frame on one that does not (GitHub Pages), a file published that is not
part of the site, or hosting settings (`_headers`, `_redirects`, `.htaccess`,
`deploy/nginx.conf`) that are wrong or disagree with each other. Also in scope: the website's
optional API under `api/` (`server/`, `functions/`: sign in with Google and the "Support this
app" payment, off until the owner configures it), such as a way to be granted a purchase
without Stripe's signed webhook, to act as or see another visitor's account, to be sent off the
site after signing in, or to make the service worker answer or keep anything under `api/`. The
API is the shared kit in `server/kit/`, the same files in every app of this account; a finding
in it is fixed there and copied to each.

Out of scope: vulnerabilities in third-party dependencies that are already
public and have an upstream fix, findings that require an attacker to already
control the device or account, and reports generated by a scanner with no
demonstrated impact.

`/.well-known/security.txt` on the website points to this page as it is on
`main`, the branch the Pages deploy publishes, and lists the two ways in above,
in that order. Its `Expires` date is renewed every year.
